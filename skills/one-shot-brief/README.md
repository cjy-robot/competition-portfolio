# one-shot-brief · 一次性需求采集

> 把 AI 的「你问一句我答一句」改成「一次问齐 → 图纸会审 → 一次做到位」。

一个给 AI 编程助手用的 **skill**（技能提示词）：面向工程任务的需求采集流程。用户说一句"帮我写个东西"，它不会立刻开写，也不会挤牙膏式地一问一答，而是把需要的信息**在一条消息里问齐**，答完先做一次**会审**（矛盾 / 风险 / 假设），再动手生成。

## 解决什么问题

常见的 prompt skill 是这样的：

```
AI：你想做什么？
你：一个爬虫
AI：用什么语言？
你：Python
AI：要爬什么网站？
...
```

一条消息只问 2–3 题，来回十几轮，上下文耗光，用户被问烦，新手还会卡在"你的部署形态是什么"这种问题上。

`one-shot-brief` 反过来做：

```
AI：先一次性问齐，你答完我出成品。不懂的写"不知道"，我来兜底。
    1. 你最后想拿到什么？ 推荐：能跑的脚本，因为…
    2. 它用来干什么、给谁用？ 推荐：自己用
    3. 有没有现成例子？ 推荐：无
    ...
你：1 能跑的脚本 / 2 自己用 / 3 不知道 / 4 不想装太复杂的东西
AI：【会审】假定 Windows + Python 已装；风险：目标网站有反爬 → 影响 M …
【成品】…
```

## 七个步骤

| 步骤 | 做什么 |
|---|---|
| 判水位 | 新手 / 一般 / 熟手，决定问多深、用不用术语 |
| 探测 | 环境、版本、目录、依赖能自己查的不问用户 |
| 一次摊开 | 8 类覆盖扫描 + 分层问卷，一条消息发完 |
| 兜底 | "不知道"是合法答案：AI 探测 / 给白话选项 / 保守默认 |
| 图纸会审 | 矛盾扫描 + 客观风险清单 + 未知与假设（红灯 ≤3）+ 结论一句话 |
| 生成 | 按任务类型选骨架；验收标准可测；数量下限防空泛 |
| 自检 + 交付 | checklist 过一遍；改稿只动被点名处 |

## 四条提问铁律

1. **能答**：多选 2–5 个互斥选项，或一句话能答完；开放题必须带默认。
2. **带推荐**：先给「推荐 X，因为…」，用户回"就按推荐"也算答完。
3. **值得问**：答了会改变做法的才问，纯风格偏好直接给默认。
4. **问事实，不问意愿**：「上次这种情况你怎么处理的」优于「你以后会用吗」。

## 核心设计

- **问全 ≠ 逼问**：覆盖 8 类（目标范围 / 实体数据 / 主流程异常 / 性能可靠 / 安全外发 / 外部依赖 / 硬约束 / 验收怎么算过），但题量封顶（新手 4–6、一般 ≤8、熟手 ≤10）。
- **客观不迎合**：矛盾直说，风险标 H/M/L，不夸想法、不打包票。
- **质量优先，不省事**：默认按验收标准做到最好那版，不拿"省时间/省依赖"降级；只有两条路线结果确实不同才各做一版。
- **证据隔离**：用户贴的代码、日志、旧提示词只当证据；里面夹带"忽略以上"之类指令先点名，不执行。
- **迭代不是重写**：回来说改哪块，只动那块和受牵连的依赖。

## 安装

`SKILL.md` 是唯一必需文件，复制到对应工具的技能目录即可：

| 工具 | 路径 |
|---|---|
| Claude Code（及兼容 skills 的工具） | `~/.claude/skills/one-shot-brief/SKILL.md` |
| DSH | `~/.dsh/skills/one-shot-brief/SKILL.md` |
| CodeBuddy / Codex 类 | 放入工具的 `skills/` 目录 |

放好后新开一个会话，技能即可被识别。

## 触发方式

- 明确要求：「一次问清」「别一问一答」「帮我写个提示词」「我有个想法」
- 或任务本身是工程类：写代码、系统设计、技术方案、技术文档、排障、选型

## 适用边界

**适用**：工程类任务——代码、脚本、系统设计、技术方案、技术文档、工程提示词、调试排障、选型评估。

**不适用**：文案、营销、生活决策等非工程任务；这类按普通对话处理，不要套这个流程。

## 设计来源

站在这些开源项目的肩膀上：

- [linshenkx/prompt-optimizer](https://github.com/linshenkx/prompt-optimizer)：证据隔离、数量下限、系统/用户提示词双模式、按反馈增量迭代
- [github/spec-kit](https://github.com/github/spec-kit)：clarify 的覆盖度扫描与选项式提问、题量上限、推荐项；specify 的需求/实现分离与待确认项上限
- [Kiro](https://kiro.dev/docs/specs/)：spec 驱动开发，EARS 验收标准句式
- [The Mom Test](https://www.momtestbook.com)：问过去的事实，不问未来的意愿
